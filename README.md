# Ziad & Hana Invitation

A static engagement invitation website with responsive design, RSVP handling,
guest messages, background music, and a protected admin view powered by Supabase.

## Features

- Responsive invitation for desktop and mobile
- Celebration countdown
- Venue map and Google Calendar actions
- Background music with manual playback control
- RSVP form with guest count
- Guest message view
- Admin-only access to the shared RSVP list
- Supabase storage with Row Level Security

## Project Structure

```text
index.html                         Main invitation and RSVP form
comments.html                      Guest and admin message view
login.html                         Admin sign-in page
auth.js                            Shared Supabase client and API helper
script.js                          RSVP, music, countdown, and page behavior
style.css                          Shared media and accessibility styles
media/                             Invitation photos and music
supabase/migrations/               Database security migration
```

## Supabase Setup

The Supabase URL and publishable key are configured in [auth.js](auth.js).
Never add a Supabase service-role key to frontend code.

### Create the RSVP table

For a new Supabase project, open **SQL Editor** and run:

```sql
create table public.rsvps (
	id bigint generated by default as identity primary key,
	name text not null,
	attending text not null check (attending in ('yes', 'no')),
	guests integer not null default 0,
	comment text not null default '',
	created_at timestamptz not null default now()
);
```

### Apply the security migration

Run [20260826_private_rsvps.sql](supabase/migrations/20260826_private_rsvps.sql)
in the Supabase SQL Editor. It is safe to run again and it:

- Adds a unique browser device ID to RSVP records
- Prevents one browser profile from submitting multiple RSVPs
- Blocks anonymous users from reading the RSVP table
- Allows anonymous RSVP inserts
- Allows only admins to read all RSVP records

### Create the admin account

In **Authentication > Users**, create an admin user with an email and password.
Then run this SQL, replacing the email address:

```sql
update auth.users
set raw_app_meta_data =
	coalesce(raw_app_meta_data, '{}'::jsonb) ||
	'{"is_admin": true}'::jsonb
where email = 'YOUR_ADMIN_EMAIL';
```

The admin signs in through `login.html`. The login page clears any previous
session when opened, so credentials are requested again.

### Configure URLs

In **Authentication > URL Configuration**, set the deployed website URL as the
Site URL. Add the GitHub Pages URL to the allowed URLs if required by Supabase.

## Guest Privacy

Guests can submit an RSVP without an account. Their latest RSVP is saved in the
browser profile and can be viewed after closing and reopening the browser.

Without login, a guest cannot be securely identified across devices. Each
browser profile receives a random device ID and can create one RSVP. Clearing
browser storage creates a new device identity. Anyone with access to the same
browser profile can see its locally saved RSVP.

Row Level Security prevents guests from reading other guests' database records.
Only an authenticated user with `app_metadata.is_admin = true` can load the
shared RSVP list.

## Run Locally

This is a static website and does not use `npm start`. From the project folder,
run:

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000/index.html` in a browser. Opening HTML files
directly may prevent browser storage, external scripts, or Supabase requests
from working correctly.

## Deploy With GitHub Pages

1. Create an empty GitHub repository.
2. Upload all project files.
3. Open **Settings > Pages**.
4. Select **Deploy from a branch**.
5. Select the `main` branch and `/ (root)` folder.
6. Click **Save** and wait for deployment.
7. Add the final GitHub Pages URL to Supabase URL settings.

The project has no build step and requires no package installation.

## Verification Checklist

- Invitation loads and images display.
- Music starts after opening and stops at the end.
- Guests can submit without logging in.
- Guests can reopen and view their saved RSVP.
- A different browser cannot read the first browser's RSVP.
- Admin login accepts the configured credentials.
- Admin can view all RSVP records.
